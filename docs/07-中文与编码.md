# 07 · 中文与编码

老游戏的中文问题从来不是「加个字体」这么简单，而是三层：**脚本编码**、**字节码/文本形态**、**渲染字符集**。

---

## 一、三层结构

| 层 | 本文涉及 | 说明 |
|---|---|---|
| 数据层 | `script/*.lua`、`data/**.txt` | 全部 **GBK**；Windows 时代产物 |
| 引擎层 | `charset.c` / `luaL_loadfile` | 引擎按 GBK 解释字节 → 转 Unicode → SDL_ttf 绘制；文本 Lua 与字节码都能加载 |
| 显示层 | 字库 | 引擎自带字库/位图字模；缺字时表现为方框 |

**关键结论：**
1. 引擎 `luaL_loadfile` **文本 Lua 与字节码都吃** —— 这给「用文本 Lua 替换字节码」开了口子（便于改脚本，代价是启动多花零点几秒现场编译）。
2. 任何改过的脚本/文本必须**按 GBK 写回**，用 UTF-8 写回就是满屏乱码。

---

## 二、乱码的两种典型形态

### 形态 A：反编译文本里的中文键变成 `.����`

反编译工具把 Lua 表的中文键（`["姓名"]`）打成 U+FFFD 占位。这类问题**不能靠猜**，要用三重依据还原：

1. 与另一份带汉字的源码做**同结构行精确配对**（行归一化后完全一致 → 取源码里的 `["中文键"]`）；
2. 按**点号左侧对象类型 + 上下文规则**推断（如 `JY.Person[..].????` 与 `["生命最大值"]` 比较 → `生命`）；
3. 最后**反查原始字节码字符串表**，确认该键名真实存在。

还原则：`.乱码` → `["中文键"]`（Lua 里中文键必须用方括号访问；写成 `.键名` 在 mod 环境的 `_G` 守卫下会被拦截）。

> 本项目 3.99 那一轮共修 499 行（其中 433 处靠同结构配对、155 处靠上下文推断、2 处字符串字面量），成品 `luac -p` 语法通过、GBK 往返一致、`\ufffd` 残留 0 处。

### 形态 B：能显示但个别字成方框

字库缺字。4.0 用的字库已覆盖常用汉字，出问题一般是「数据里混进了字库没有的生僻字/符号」。处理：换字库或替换该字符，**不要改引擎字符集转换逻辑**。

---

## 三、编码相关的硬规则

1. **写回必须 GBK**：`text.encode('gbk')`，遇到无法编码字符要报错，不要 `errors='replace'`（那样会静默丢字）。
2. **换行保持 CRLF**（原文件是 CRLF 时），不要顺手改成 LF —— 某些文本解析按行切分时对 `\r` 敏感。
3. **改字节码里的数值常量风险极高**：没有源码可回退、错一个就崩或乱码。优先改文本 Lua。
4. **不要用「文字放大」解决可读性**：字号一变排版全废（见 [04](04-画面尺寸与遮罩.md) 第六节）。

---

## 四、验证清单

| 检查 | 方法 |
|---|---|
| 语法 | `luac -p 文件`（返回 0） |
| 编码往返 | `s.encode('gbk').decode('gbk') == s` |
| 无 U+FFFD | 全文搜 `\ufffd` 应为 0 |
| 无点号中文 | 搜 `.中文` 形式访问应为 0 |
| 真机 | 启动到进游戏，`error.txt` 无 `syntax error` / `attempt to index`，界面无乱码 |

## 五、可复用的操作

```bash
# 反汇编设备上真正在跑的那份脚本（先拷到纯 ASCII 路径，luac 不认中文路径）
luac -l -l jymain.lua > dev_dis.txt

# 在反汇编里按 GBK 八进制转义搜中文串
python find_help.py
```

```python
# 读 GBK 源码
s = open(p, 'rb').read().decode('gbk', 'replace').replace('\x00', '')
# 写回
open(p, 'wb').write(s.encode('gbk'))
```

## 六、坑

- **多份 `jymain.lua` 副本**（`mod0/`、`mod4/`、字节码/文本、大小不同）—— 必须以 `config.lua` 里 `CONFIG.JYMain_Lua` 指向的那份、也就是**设备上实际加载的那份**为准；拿本地别的版本比对会得出错误结论。
- 反编译工具在不同 Lua 版本（32 位 chunk / 64 位 chunk）间不通用，`luac` 也要对版本。
- 用 UTF-8 BOM 写 Lua 会让引擎在首行多出一个不可见字符，可能触发语法错误。
