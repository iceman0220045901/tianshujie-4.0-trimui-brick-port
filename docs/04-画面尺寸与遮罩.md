# 04 · 画面尺寸、缩放与遮罩

这一章解决一个最容易反复折腾的问题：**内部渲染面到底设多大、缩到多少、黑边怎么办。**

---

## 一、先摆事实：4.0 是按 1280×720 排版的

初始假设是「老游戏就是 640×480，放大 1.5 倍到 960×720」。实测不成立。

| 证据 | 内容 |
|---|---|
| 声明层 | `set.ini`：`CONFIG.Width = 1280`、`CONFIG.Height = 720` |
| 图片层 | 全包 416 张 png/bmp 扫尺寸，**唯一全屏级**是 `data/pic/TITLE.png` = **1280×720**（标题整幅按屏宽画死） |
| 脚本层 | `jymain.lua` 命中浮点常量 `1280.0`；`jyconst.lua` 命中 `720.0 / 480.0 / 960.0`（战斗行高、血条宽度一类） |
| 引擎层 | `sdlfun.c` 贴图按原始尺寸居中：`x=(g_ScreenW - pic->w)/2` —— 任何按 1280 宽排的整幅面板，在 960 面上必然被裁 |

**症状对照**（`JY_SURF_W=960` 时）：载入进度行文本两端被切、标题右侧四册书整块消失。改回 1280×720 后同一屏 1~11 行完整、书册出现。

---

## 二、结论：内部面 ≥ 排版宽度，面板不够就等比缩

```
内部渲染面  1280×720  （与 4.0 排版一致，绝不裁边）
输出到面板  1024×576  （JY_FB_SCALE=0.8，满宽、不变形）
上下         96 px 黑边 → 用机框遮罩盖掉
```

### 为什么是 0.8 而不是 0.75 / 0.9

| 方案 | 画面 | 结果 |
|---|---|---|
| 0.75 | 960×540 | 左右各 32 px 空边，画面小、字更小 |
| **0.8** | **1024×576** | **满宽、无左右空边，能完整显示全部内容的临界点** |
| 0.9 | 1152×648 | 超出面板宽度，左右被裁 |
| 1.0 / 拉伸 | 1280×720 / 1024×768 | 裁边或纵向拉长 1.33 倍变形 |

0.8 是 1024×768 面板上「不裁边、不变形」的最大等比。想更大只能接受裁边（丢界面）或拉伸（变形），**这是 4.0 稿子只有一版 1280×720 排版造成的物理上限**。

> 想改大：必须先重画 `TITLE.png` 等全屏级界面图，再逐处改 `jymain.lua` 的坐标常量 —— 而它是**编译后字节码**，改数值常量风险极高（错一个就崩溃/乱码），所以本项目停在 0.8。

---

## 三、缩放算法：最近邻 → 盒式平均

**问题**：0.8 下最近邻是「每 4/3 个源像素丢掉 1/3」，中文细横线正好被丢，字看着费眼。

**做法**：缩小（`dst < src`）时改成**盒式平均（area / box filter）**：每个目标像素取它覆盖的源像素块（通常 2×2）做通道平均。

```c
/* tools/fbdev_block.c JY_FbBlit() */
g_FbXS0[x], g_FbXS1[x]   /* 目标列 x 覆盖的源列区间 */
g_FbYS0[y], g_FbYS1[y]
recip[n]                 /* 倒数查表，避免逐像素整数除法 */
```

放大仍是最近邻（不引入模糊）。

**代价实测**：

| 配置 | 单核占用（10 s 采样） | 观感 |
|---|---|---|
| 0.75 + 最近邻 + 整圈框 | ≈66% | 字小、笔画断 |
| 0.75 + 盒式 + 整圈框 | ≈89% | 笔画连续，但框占面积 |
| **0.8 + 盒式（现默认）** | **≈79%** | 满宽、字最大且不变形 |

多花约 13 个百分点换笔画连续；觉得卡就把 `JY_FB_SCALE` 回 0.75。

## 四、上下机框遮罩

### 4.1 为什么不是整圈机框

整圈 CRT 框（孔 1054×784）在 0.75（960×540）下刚好收在面板内；一改 0.8（1024×576）就**左右各超 42 px，框被面板裁断**。所以改成「只在上下两条边有内容」：画布 1024×768，镂空正好 `(0,96)-(1023,671)` = 1024×576。

### 4.2 三张候选

| 文件 | 来源 | 适用 |
|---|---|---|
| `bars-crt.png`（默认） | `make_bars2.py` 程序生成：70 px 机身 + 70 px 凹槽 + 内沿渐亮 | 0.8 |
| `bars-crt2.png` | 把整圈 CRT 框的上下边带双线性拉伸成 1024×96 | 0.8 |
| `bars-wsc.png` | 从模拟器 WSC 遮罩抽上下边带（带机种字样） | 0.8 |
| `crt-visible.png` | 整圈 CRT 框（要同时 `JY_FB_SCALE=0.75`） | 0.75 |

### 4.3 引擎侧实现

`JY_FB_OVERLAY=<png>`：

1. `IMG_Load` → 转 ARGB8888；
2. 从中心 BFS 量出镂空矩形（`png_hole.py` 同一算法）；
3. 按 `k = max(画面宽/孔宽, 画面高/孔高)` 缩放、孔中心对齐画面中心；
4. **预合成「底色 + 遮罩」缓存**，每帧只重绘画面外的四条边带 —— 孔与画面比例一致时 `k=1`，画面像素一个都不动。

### 4.4 已知残留

0.8 缩放后画面自身最上沿约 3 px 是黑的（1280×720 → 1024×576 首行不足一像素），遮罩内沿与它之间有一道细缝。彻底消掉要让遮罩多吃 4 px 画面，**没有这么做**（宁可留缝，不裁画面）。

## 五、可调参数（只改 `launch.sh`，不用重编）

| 目标 | 设置 |
|---|---|
| 现默认（满宽最清楚） | `JY_SURF_W=1280 JY_SURF_H=720 JY_FB_SCALE=0.8`，`JY_FB_OVERLAY=overlays/bars-crt.png` |
| 要整圈 CRT 框 | `JY_FB_SCALE=0.75` + `JY_FB_OVERLAY=overlays/crt-visible.png` |
| 要满屏但接受变形 | `JY_FB_SCALE=0`，注释 overlay |
| 纯黑边不要遮罩 | 注释 `JY_FB_OVERLAY` |

## 六、关于「把文字放大」的一次失败尝试（记录以免重走）

**想法**：引擎侧把文字整体按 1.15 倍绘制，让 0.8 下的字更清楚。

**结果**：直接否决并回滚 —— 字放大后**字符超出对话框边框**，要改的地方太多（所有带框的界面、行高、换行宽度都要跟着改）。

**教训**：在这类「排版写死在字节码里」的老游戏上，**改字号等于改排版**，成本远高于收益；提高可读性应从「缩放算法 + 画面比例」入手，不要动字形尺寸。
