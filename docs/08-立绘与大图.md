# 08 · 立绘与大图：从「补回 zoom」到「固定框 146」

这是本项目**迭代次数最多**的一节，也是最能体现「照抄旧版做法」价值的一节。

---

## 一、现象

- 对话里的人物立绘，有些铺满半屏，有些小得像个摆设；
- 战斗属性面板的头像同样偏大；
- mod 后加的立绘看起来"正常"，原版人物明显偏小。

---

## 二、逐个根因

### 2.1 引擎把 `zoom` 参数丢掉了

旧版 3.45.1 的 `hotfix.lua` 是「按框等比算 zoom 再交给引擎」：

```lua
local w,h = lib.GetPNGXY(1, headid*2)
local zoom  = math.modf(math.min(picw*100/w, pich*100/h))   -- 按对话框/属性框算
lib.LoadPicture(CC.HeadPath .. headid .. ".png", x, y, zoom)
```

而我们的引擎（jysdl-bh SDL2 分支）原来：

```c
int x = (int)lua_tonumber(pL, 2);
int y = (int)lua_tonumber(pL, 3);
JY_LoadPicture(str, x, y);        /* 第 4 个参数 zoom 被直接丢掉 */
```

`JY_LoadPicture()` 只做 `SDL_BlitSurface` 原尺寸贴、`x=-1&&y=-1` 时按 `(g_ScreenW - pic->w)/2` 居中。→ **4.0 算好的缩放百分比全被丢弃**，`data/head` 里 705×705 的图在 1280×720 画布上占掉半屏。战斗属性框更小，同一张图贴上去显得更大。

修法：

- `luafun.c` `HAPI_LoadPicture` 读出第 4 个参数并透传；
- `sdlfun.c` 绘制时 `dw = pic->w*zoom/100`、`dh = pic->h*zoom/100`，等尺寸走 `BlitSurface`，否则 `BlitScaled`；居中按 `dw/dh` 算；
- **只对 `data/head` 下的图生效**（路径大小写不敏感匹配 `head`），界面/地图/文字保持 1:1。

### 2.2 4.0 给小图传的是「放大倍率」（>100）

补回 zoom 后立刻翻车：小村「双儿」剧情里，200 px 的图被放大约 5 倍，整张脸铺满 1024×768。原因是这一处 4.0 传的 zoom 是「把图铺满画面的倍率」。

第一版修法：**只缩不放**

```c
if (zoom <= 0) zoom = 100;
if (zoom > 100 && !g_HeadZoomAll) zoom = 100;   /* 放大一律忽略，除非 JY_ZOOM_ALL=1 */
```

### 2.3 「只缩不放」把原版小头像压成了拇指图

客栈「店小二」对话里，那张头像只有约 40×70 px —— 4.0 给这些小图传的正是 >100 的放大 zoom，而我们把它按 100 处理，于是小图再也不放大。**这与用户反馈的「原版立绘太小、mod 立绘正常」完全对应。**

### 2.4 旧版天书劫真正的做法：固定框

看旧版 3.45.1 `hotfix.lua`（`TalkEx_fixed`）：

```lua
local picw = 73 * CC.Zoom      -- CC.Zoom = CONFIG.Height/360 = 720/360 = 2  → 146
local pich = 73 * CC.Zoom      --                                            146
local w, h = lib.GetPNGXY(1, headid*2)
local zoom = math.modf(math.min(picw*100/w, pich*100/h))
local x = (picw - w*zoom/100) / 2      -- 在框内居中
local y = (pich - h*zoom/100) / 2
lib.LoadPicture(CC.HeadPath .. headid .. ".png", 框x + x + 3, 框y + y + 3, zoom)
```

要点：

1. **框尺寸写死 146×146**（`73 × CC.Zoom`），外面画白框，人名在框上方；
2. **只缩不放**：`zoom = min(146*100/w, 146*100/h)` —— 素材 705 还是 100 都塞进 146；
3. **战斗属性头像单独一档 130**（`65 * CC.Zoom`，`WarShowHead_fixed`）；
4. 与素材尺寸**完全解耦** —— 这才是「旧版从不显大也不显小」的真正原因。

---

## 三、最终方案：固定框（`JY_HEAD_FIT`）

```c
/* sdlfun.c JY_LoadPicture，仅在 data/head 且 g_HeadFit > 0 时 */
int m = pic->w > pic->h ? pic->w : pic->h;
if (m > 0) { zoom = g_HeadFit * 100 / m; if (zoom < 1) zoom = 1; }
```

```sh
export JY_HEAD_FIT=146     # 与旧版对话立绘同档（1280×720 画布像素）
export JY_HEAD_MAX=0       # 关闭"最长边封顶"，两者不要同时用
```

**语义定死**：`data/head` 下的图，**最长边恒等于 146**；大图缩、小图放大，与素材尺寸无关。

真机验证：

- 开场对白「哎我了个去！头好疼啊！」—— 徐小侠头像 146，不再铺满屏；
- 客栈「店小二」对话 —— 原版小头像也放大到 146，不再像摆设；
- 开场战斗 —— 右侧属性面板立绘同样 146（旧版这一档 130，我们大 12%，可按需把战斗单开一档）。

## 四、素材侧仍需收一次（可选）

`data/head` 405 张，最长边分布 min 36 / median 203 / max 705。固定框之后运行时已经"压平"，但**预缩素材仍有好处**：解码内存小、帧时间稳（1 GB 内存无 swap 的机器上尤其明显）。

```powershell
python tools\head_fix.py "<4.0 原始 data\head>" head-fix200 200   # 最长边 200 封顶
```

`head_fix.py` 是纯 Python（自写 PNG 解码/编码 + 盒式平均），不需要 PIL；命中 205 张，覆盖上机后 `120.png` 200×200、`70.png` 200×200、`394.PNG` 200×196。

## 五、参数速查

| 目标 | 设置 |
|---|---|
| 与旧版一致（推荐） | `JY_HEAD_FIT=146`、`JY_HEAD_MAX=0` |
| 想更大 | `JY_HEAD_FIT=160~200` |
| 只封顶不放大（旧方案） | `JY_HEAD_FIT=0`、`JY_HEAD_MAX=160` |
| 尊重脚本的所有 zoom（含放大） | `JY_ZOOM_ALL=1` |

---

## 六、教训

1. **不要「想当然地」把 >100 的 zoom 一律按 100 处理** —— 老游戏里 >100 恰恰是「把这张小图放大到框里」的正常语义；
2. **素材尺寸不齐不等于要改素材**：固定框就能一次抹平，素材预缩只是性能优化；
3. **照抄旧版同作品的移植做法**，比自己推公式可靠得多（旧版的 146/130 就是答案）；
4. 立绘相关改动**只对 `data/head` 生效**，避免影响界面排版。
