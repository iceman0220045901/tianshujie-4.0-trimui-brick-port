# 11 · 故障排查手册

按「症状」查，不要按代码查。每条都给了判定方法和处置。

---

## A. 启动类

### A1「双击进不去 / 一闪就没」

| 判定 | 处置 |
|---|---|
| `cat /tmp/jysdlbh_diag.log` 看 `exit code=` 与 `elapsed=` | 若 <15 s 反复退出，可能是读卡抖动或初始化失败 |
| `cat /tmp/jysdlbh.log`、端口目录 `error.txt` | 有无 `GLIBC_2.xx not found`（glibc tag 太高）、缺 `.so` |
| `ls -l jysdllua` 权限 | FAT32 一律 `chmod 777` |

> **诊断版二进制**：用 `build_dbg.ps1` 编一份打开错误日志的版本；release 版可能把 SDL 初始化错误吞掉，表现为「静默退出」。

### A2 Ports 菜单里看不到项目

`Ports/<目录>/` 下必须有 `config.json`（`label`/`icon`/`background`/`launch`）、`launch.sh`、`icon.png`、`bg.png`。缺描述文件就不生成条目（不是"有目录就列"）。补好后重进 Ports 菜单，仍不显示就重启一次。

### A3 黑屏但进程在

- 抓帧确认：`dd if=/dev/fb0 of=/tmp/x.raw bs=4096 count=768` → `raw2png.py`；
- 抓到的是 MainUI 画面 → 直写被盖住：确认 `launch.sh` 里的 `kill -STOP MainUI` 生效、`/tmp/jy4_ui_paused` 存在；
- 抓到全黑 → 检查 `JY_FB_SCALE`、`JY_SURF_W/H` 是否被改坏（例如 `JY_SURF_W=960` 会裁边但不至于全黑）。

## B. 画面类

### B1 文字/贴图被切边（左边半行、右侧装饰消失）

**根因几乎总是内部渲染面小于排版宽度。** 查 `set.ini` 的 `CONFIG.Width`（本例 1280），把 `JY_SURF_W/H` 设成同值，再靠 `JY_FB_SCALE` 缩小。

### B2 画面上下有黑边 / 边框被裁

- 黑边是 1280×720 → 1024×576 的必然结果，用 `JY_FB_OVERLAY`（上下机框）盖；
- 边框被裁说明遮罩缩放后超出面板：0.8 时不要用整圈框（左右会超 42 px），改上下框或 `JY_FB_SCALE=0.75`。

### B3 中文笔画断、看着累

缩小算法是最近邻 → 换盒式平均（`tools/fbdev_block.c` 的 `JY_FbBlit()`），代价约 +13% 单核。**不要试图放大字号**（会把排版撑坏）。

### B4 画面撕裂

直写是单缓冲无 vsync，快速横移可见。要彻底解决得用 `FBIOPAN_DISPLAY` 双缓冲（未实现）。

## C. 输入类

### C1 画面正常、按键无反应

1. `pidof gptokeyb` 是否在？
2. `gptokeyb` 是否在读手柄：`ls -l /proc/<pid>/fd` 应有 `/dev/input/event3` 与 `/dev/uinput`；
3. 虚拟键盘是否存在：`cat /sys/class/input/input*/name | grep -i fake`；
4. 引擎是否收到键：`JY_KEYLOG=1 ./jysdllua`，按一次键看 `keylog.txt` 有无 `sym=`。

### C2 某个键不对 / A、B 键反了

改 `jysdllua.gptk`（`键名 = 键盘键`），重启 port 即可，不用重编。

### C3 注入按键时游戏乱跳

`jyinject` 节奏太快丢键。每个键后加 `w1`。

## D. 音频类

### D1 完全没声音

按顺序：

1. `aplay` 能否出声（排除 ALSA/独占）；
2. `cat fbdev.txt | grep -i music`：有 `PlayMIDI called` 但 `FAIL code=41` → 解码入口错（要用 `BASS_MIDI_StreamCreateFile`）；
3. 路径大小写：`case-fix` 日志说明脚本要小写、卡上是 `.MID`（已兜底）；
4. `CONFIG.MP3` 是否为 1（要改 0，否则音色库不挂）；
5. 音量：`JY_MUSIC_VOL` / `JY_SOUND_VOL` 是否太低；
6. 默认开关：`JY.EnableMusic` 是否被 `JY_MUSIC_DEFAULT=0` 关掉。

### D2 有 BGM 但没音效

已确认版本里音效正常（战斗内可听到）。若又出现无声：

1. `JY_SOUND_VOL` 先从 40 提到 60，排除"音量太小听不见"；
2. `JY_BGM_DBG=1` 打开 Lua 侧调试，看 `fbdev.txt` 是否有 `sfx` 行与 `FAIL code=N`；
3. `code=2` = 文件打不开 → 查 `data/sound/` 下对应文件是否存在、扩展名大小写是否一致；
4. 若日志显示文件打开成功但仍无声，再怀疑音效走的是 BASS sample 通道而非 stream 通道。

## E. 资源/脚本类

### E1 某功能「点了直接退回游戏」

优先怀疑**资源存在性判断**（`existFile` / `access`）：路径大小写、文件缺失、编号不连续。判定：把猜测的路径在设备上 `head` 一下。

### E2 满屏乱码

编码被写成 UTF-8。改脚本必须按 **GBK** 写回；文本 Lua 与字节码引擎都吃，但编码必须对。

### E3 启动报 `syntax error`

- 改文本 Lua 时语法错；用 `luac -p` 先在 PC 侧验证；
- 也常见于 UTF-8 BOM 被写进 Lua 首行。

## F. 系统/设备类

### F1 误杀 MainUI 后屏幕变成设置页

```sh
cd /usr/trimui/bin
export LD_LIBRARY_PATH=/usr/trimui/lib
setsid ./MainUI > /tmp/mainui.log 2>&1 &
```

**不要 `pkill -9 MainUI`**，会让 `runtrimui.sh` 循环退出。

### F2 想重启设备

`reboot` 在本机被安全策略硬性拦截，**不要尝试**；请用户手动重启。

### F3 推文件后不生效

- 有没有 `mv -f` 覆盖？（推成 `.new` 后忘了改名很常见）
- md5 是否一致：`md5sum 文件 | cut -c1-32`；
- 有没有残留旧进程还在跑：`pidof jysdllua`。

---

## G. 三条硬规矩

1. **先抓帧，再改代码** —— 用户看到的「没反应」，未必是你以为的那个原因。
2. **一次只改一个变量** —— 内部面、缩放、遮罩、音量、立绘，同时改就说不清是谁的功劳。
3. **改完必须留证据** —— 抓帧 + 日志 + 进程状态，三者对齐才算闭环。
