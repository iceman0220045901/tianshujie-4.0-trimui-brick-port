# 10 · 内置攻略与「已做剧情变色」

这是本项目最后一个坑，也是很典型的一类问题：**功能确实做了，只是资源路径差一个字母，表现成「点了没反应」。**

---

## 一、功能机制（从设备上实际运行的脚本得出）

以下行号对应可读中文源 `天书劫代码（内含一部分汉字）.lua`（GBK，564,644 B），与设备上的字节码同结构。

### 1.1 菜单：`TSInstruce()`（源 :14694）

```lua
for i = 1, math.huge do
    local f = string.format("%s%d.txt", CONFIG.HelpPath, i)
    if not existFile(f) then break end          -- 缺号即 break
    -- 读第一行当菜单项
end
ShowMenu2_new(menu, #menu, 3, 12, ...)          -- 3 列 × 12 行
```

- **资源存在性驱动**：`1.txt` 必须存在、文件名必须**连续**，缺一个就停；
- 每本取**第一行**当菜单项显示；
- `#menu == 0` 时直接 `Cls(); return` —— **这就是「点了直接回游戏」**，不报错、不写日志。

### 1.2 正文：`InstruceTS(id)`（源 :14826）

```lua
local filename = CONFIG.HelpPath .. id .. ".txt"
if not existFile(filename) then filename = CONFIG.CurrentPath .. "update.txt" end
TSGL(filename, id)
```

### 1.3 变色：`TSGL()`（源 :14742）—— 关键在这里

```lua
for k = 1, #str do
    local s, e = string.find(str[k], "'%x+'")     -- 找单引号十六进制标记，如 '19'
    if s then
        tsnum = tonumber(string.sub(str[k], s+1, e-1), 16)
        if JY.GLTS[id-1][tsnum] == 1 then          -- 该事件已完成
            color = RGB(120, 208, 88)              -- 绿色
            把标记替换成 "（完成）"
        else
            color = C_WHITE                        -- 白色
            删掉标记
```

- 文本里 `'19'` 这种单引号数字 = **剧情事件号**；
- `JY.GLTS[书号-1][事件号] == 1` 判完成；
- 完成后整行染绿并追加「（完成）」，未完成保持白字、标记不可见。

### 1.4 进度来源（源 :5114~5134）

```lua
if CC.GLTS[i][j] == eventnum then JY.GLTS[i][j] = 1 end
```

剧情事件执行过就打点，**跟着存档走**（换存档变色会跟着变）。

### 1.5 路径真相（从设备 `config.lua` 字节码反汇编确认）

```
CONFIG.DataPath  = "data/"
CONFIG.HelpPath  = CONFIG.DataPath .. "Help/"      →  data/Help/     （大写 H）
```

> 早期只从字符串表看到 `"Help/"`，误判成「相对工作目录」，在端口根目录建了 `Help/`，重试仍失败 —— 就是漏了 `DataPath` 前缀。

### 1.6 `existFile()`（源 :12693）

```lua
function existFile(filename)
    local f = io.open(filename)
    if f == nil then return false end
    io.close(f)
    return true
end
```

就是 `io.open` 能不能成功 —— **所以路径大小写错了就必然 false**。

## 二、真机排查过程（含两条弯路）

| 步骤 | 动作 | 结果 |
|---|---|---|
| 1 | 读源码 + 反汇编，确认 `TSInstruce` 的资源存在性逻辑 | 确定"空菜单 → 静默返回"的机制 |
| 2 | 反汇编设备 `config.lua`，得到 `HelpPath = data/Help/` | 路径真相 |
| 3 | 在端口根目录建 `Help/`（16 txt） | **仍然打不开** —— 弯路①：漏了 `DataPath` |
| 4 | 写 LD_PRELOAD 日志 shim（`tools/jyopen.c`，拦 `open/fopen`） | **一条日志都没有** —— 弯路②（见下） |
| 5 | 改用确定性对照实验：`head data/Help/1.txt` vs `head data/help/1.txt` | 一个 No such file、一个正常 → 确认 FAT32 大小写敏感 |
| 6 | 两步改名：`mv help hlp_tmp && mkdir Help && cp hlp_tmp/*.txt Help/` | 目录就位，**无需重启游戏** |
| 7 | 游戏内 `esc → 系统 → 系统攻略`，抓帧 | **16 本全出来** |
| 8 | 点开《鸳鸯刀》，抓帧 | 第 1/2/4 条**绿色带「（完成）」**，3/5/6/7 白字 → 变色功能正常 |

### 弯路①：只建了根目录的 `Help/`

只凭字符串表里的 `Help/` 就往端口根建目录，重试无效。**教训：路径常量往往是拼接出来的，必须看赋值上下文。**

### 弯路②：LD_PRELOAD 的 open/fopen 日志 shim 不出日志

```c
/* tools/jyopen.c：拦 open/open64/fopen/fopen64，记录含 "Help" 的路径 + 返回码 + errno */
```

编译（zig，aarch64-linux-gnu.2.33）后 `LD_PRELOAD=$PWD/jyopen.so sh launch.sh` 启动，`/proc/<pid>/maps` 显示 `.so` 已加载 7 段，但 `/tmp/jyopen.log` **始终不存在**。

推测 glibc 内部走的是 `__open64_2`、`openat` 等未被我 hook 的入口，或 fortify 把调用内联了。**结论：不要把它当唯一取证手段**，改用「同一路径两种大小写直接 `head`」这种确定性实验，成本更低、结论更硬。

## 三、最终状态

设备上：

```
/mnt/SDCARD/Ports/jysdlbh/data/Help/                 16 个 txt（大写，引擎实际读取位置）
/mnt/SDCARD/Ports/jysdlbh/data/help_orig_lowercase/  原小写目录备份（16 个）
```

- 端口根目录那个多余的 `Help/` 已删除；
- `data/Help2`、`data/Hh` 等测试目录已删除。

**以后更新攻略内容**：直接把新的 txt 覆盖到 `data/Help/`（大写 H）即可，**标记格式别动**，否则变色失效。

## 四、这套机制能怎么用（给移植者）

1. **补攻略**：往 `data/Help/` 放 `1.txt … N.txt`（连续编号），每本第一行是书名，正文行尾写 `'<十六进制事件号>'`；
2. **改书名/加书**：注意 16 本已按 4 列 × 4 行排好，加书要同时确认菜单格数够；
3. **修复别人的版本**：如果某版本「系统攻略」点了没反应，第一件事是检查 `data/Help` 是否存在且大小写正确、`1.txt` 是否在、编号是否连续；
4. **变色不生效**：说明 `JY.GLTS` 没有打点（存档里这些事件没做过），或 txt 里的标记被清掉了。

---

## 五、通用教训（可套用到任何「点了没反应」的功能）

1. 先分清「功能没实现」和「资源没找到」——**静默返回**通常是后者；
2. 找到菜单的**资源存在性判断**（`existFile` / `access` / `fopen`），顺着路径查到底；
3. 路径必须从**设备上实际运行的那份**字节码/脚本里取，不要用本地别份版本；
4. 大小写这种「差一个字母」的问题，用一条 `head` 就能证伪，比写 shim 快得多；
5. 修完必须**抓帧留证**（列表页 + 内容页各一张），否则下次又说不清。
